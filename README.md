# كاشير فول وطعمية — نظام نقاط بيع أوفلاين

نظام كاشير كامل بواجهة عربية (RTL) لمطعم فول وطعمية مصري، يعمل بنسبة 100% بدون إنترنت.

## المتطلبات

- Node.js 18 أو أحدث

## التشغيل محليًا

```bash
npm install
npm run dev
```

ثم افتح الرابط الذي يظهر في الطرفية (عادة `http://localhost:5173`).

## بناء نسخة الإنتاج

```bash
npm run build
npm run preview   # لمعاينة نسخة الإنتاج محليًا
```

ملفات الإنتاج الناتجة في مجلد `dist/` عبارة عن صفحة ويب ثابتة بالكامل — يمكن نسخها على أي جهاز
(حتى بدون إنترنت) وفتحها عبر أي خادم ملفات ثابت محلي.

## التقنيات المستخدمة

React 19 + Vite · Redux Toolkit · React Router · Tailwind CSS v4 · Lucide Icons · Recharts (رسوم بيانية) ·
LocalStorage فقط لكل بيانات التطبيق (لا يوجد IndexedDB)

لا يوجد أي اتصال بخادم خلفي أو قاعدة بيانات سحابية أو أي API خارجي.

## هيكل المشروع

```
src/
├── app/            # متجر Redux، خطاف init، طبقة الحفظ التلقائي
├── components/      # مكونات قابلة لإعادة الاستخدام (common, layout, pos, products, orders)
├── pages/           # صفحات التطبيق (الرئيسية، الكاشير، الطلبات، المنتجات، التصنيفات، التقارير، الإعدادات)
├── features/        # شرائح Redux Toolkit لكل نطاق بيانات
├── services/        # التخزين المحلي (IndexedDB/localStorage)، النسخ الاحتياطي، الطباعة
├── utils/           # دوال مساعدة (تنسيق العملة، حسابات التقارير...)
├── data/            # بيانات مبدئية (منتجات وتصنيفات مطعم فول وطعمية)
└── routes/          # تعريف مسارات React Router
```

## كيف يعمل التخزين بدون إنترنت

جميع بيانات التطبيق — بلا استثناء — تُخزَّن في **LocalStorage فقط**. لا يوجد أي استخدام لـ IndexedDB
في المشروع.

- **طبقة تخزين مركزية واحدة**: كل قراءة أو كتابة إلى LocalStorage تمر عبر
  `src/services/storage/storage.js`، وهو الملف الوحيد في المشروع الذي يتحدث مباشرة إلى
  `window.localStorage`. يوفر دوال JSON آمنة (`readJSON`/`writeJSON`) مع معالجة أخطاء كاملة،
  بالإضافة إلى دوال مخصصة لكل نوع بيانات (`loadProducts`/`saveProducts`، `loadOrders`/`saveOrders`،
  إلخ).
- **مفتاح مستقل لكل نطاق بيانات**: المنتجات، التصنيفات، الطلبات، الإعدادات (تشمل معلومات المطعم
  وإعدادات الفاتورة ورقم القفل PIN)، وسلة الطلب الحالية — كل منها في مفتاح `localStorage` منفصل
  (`foul_pos_products`, `foul_pos_categories`, `foul_pos_orders`, `foul_pos_settings`,
  `foul_pos_cart`). هذا يمنع تلف نطاق بيانات من التأثير على البقية، ويجعل كل عملية كتابة أسرع لأنها
  لا تُعيد تسلسل بيانات لم تتغيّر.
- **تحميل تلقائي عند بدء التشغيل**: `src/app/initializeApp.js` يقرأ كل المفاتيح من LocalStorage عند
  فتح التطبيق، ويتحقق من صحة كل عنصر (نوع صحيح، حقول أساسية موجودة...)، ويتجاهل أي سجل تالف بدلاً
  من تعطيل التطبيق. في أول تشغيل (لا توجد بيانات محفوظة) يتم زرع بيانات مبدئية واقعية لمطعم فول
  وطعمية (`src/data/seedData.js`) وحفظها فورًا.
- **حفظ تلقائي عند أي تغيير**: `src/app/persistenceMiddleware.js` middleware مخصص لـ Redux يلتقط
  كل تصرف (action) يُغيّر بيانات المنتجات/التصنيفات/الطلبات/الإعدادات/السلة، ويكتب النسخة المحدثة من
  الحالة إلى LocalStorage فور حدوثها — فلا حاجة لأي زر "حفظ" يدوي، ولا تُفقد أي بيانات عند تحديث
  الصفحة أو إغلاق التبويب أو إعادة تشغيل الجهاز.
- **معالجة الأخطاء**: كل قراءة/كتابة محاطة بـ `try/catch`. إذا تعذّر الوصول إلى LocalStorage (وضع
  التصفح الخاص، تجاوز الحد المسموح للتخزين، متصفح قديم لا يدعمه...) يعمل التطبيق ببيانات مبدئية في
  الذاكرة بدلاً من التعطل، مع إشعار Arabic toast للمستخدم.

## النسخ الاحتياطي والاستعادة

من صفحة **الإعدادات → إدارة البيانات**:
- **تصدير البيانات**: ينشئ ملف JSON يحوي المنتجات والتصنيفات والطلبات والإعدادات، ويُنزَّل مباشرة.
- **استيراد البيانات**: يقرأ ملف JSON، يتحقق من صحة بنيته، ثم (بعد تأكيد المستخدم) يستبدل به كل
  البيانات الحالية في LocalStorage عبر نفس middleware الحفظ التلقائي.
- **حذف جميع البيانات**: يتطلب كتابة كلمة تأكيد صريحة قبل حذف كل شيء والعودة للبيانات المبدئية.

## قرارات وملاحظات مهمة

- **الخطوط**: تم استخدام خطوط النظام (Tahoma / Segoe UI / Arial) بدلاً من خط مُحمَّل من الإنترنت،
  لضمان عمل الواجهة العربية بشكل كامل دون أي اتصال بالشبكة حتى في أول تشغيل للتطبيق.
- **الطباعة**: تتم عبر `window.print()` في نافذة مخصصة بتنسيق مهيأ لطابعات الإيصالات الحرارية
  (عرض 80mm)، ولا تعتمد على أي مكتبة أو خدمة خارجية.
- **قفل الكاشير بـ PIN**: ميزة اختيارية بالكامل من الإعدادات، محلية فقط، ولا ترتبط بأي نظام حسابات.
- **حساب المبالغ**: يتم تقريب كل العمليات الحسابية إلى خانتين عشريتين لتفادي أخطاء الفاصلة العائمة.
- **الأداء**: تم الاكتفاء بحزمة JS واحدة (bundle) لتبسيط النشر بدون خادم؛ يمكن تقسيمها لاحقًا بسهولة
  عبر `React.lazy` إذا كبر المشروع أكثر.

## الاختبار

تم بناء المشروع والتحقق من نجاح `npm run build` بدون أخطاء، وتشغيله عبر `npm run preview` للتأكد من
صحة الحزمة الناتجة. جرّب يدويًا: إضافة منتجات للسلة، الخصم بالنسبة والمبلغ الثابت، الدفع النقدي
(تحقق من رفض المبلغ غير الكافي) والبطاقة والمحفظة، طباعة الفاتورة، إدارة المنتجات والتصنيفات،
التقارير حسب الفترة، النسخ الاحتياطي والاستيراد، الوضع الداكن/الفاتح، وتحديث الصفحة للتأكد من
بقاء البيانات.
